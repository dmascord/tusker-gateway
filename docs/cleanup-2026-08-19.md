# Tusker Gateway Cleanup Plan — 2026-08-19

## Scope
Bring `tusker-gateway/` to a maintainable shape, decouple auth-specific logic from
`passthrough.py`, lock down provider/credential configuration with typed models,
consolidate duplicated Copilot constants, and add a persistent cooldown record so
429 windows survive restarts.

## Acceptance criteria
Each task below must:
1. Be expressed as a change to one or more files under `tusker-gateway/`.
2. Preserve existing public API used by tests (`PassthroughClient.chat`,
   `CodexTokenRotator.get_token/advance`, `load_auth_file`, `save_auth_file`,
   `PROVIDER_ENDPOINTS` keys).
3. Keep deterministic tests green (the 69-provider/auth-test set).
4. Add at least one new deterministic test for the new behaviour.

## Tasks

### T1 — Extract authentication request logic
Move the oauth + bearer header assembly out of `PassthroughClient._build_request`
into a small `Authenticator` interface (`tusker_gateway/auth_strategies.py`) that
returns `(headers, body)` for a provider. `PassthroughClient` keeps request
orchestration only.

### T2 — Typed provider and credential models
Replace raw `dict[str, Any]` shapes with `pydantic` models:
- `ProviderConfig` for entries in `PROVIDER_ENDPOINTS`.
- `Credential` for entries in `auth.json` `credential_pool`, with both Hermes
  (`access_token`, `expires_at_ms`) and legacy (`token`, `expires_at`) support.
A `from_raw()` / `to_raw()` pair keeps interop with disk and env JSON unchanged.

### T3 — Consolidate Copilot constants and helpers
Create `tusker_gateway/copilot_constants.py` and move `_JWT_REFRESH_MARGIN_SECONDS`,
`_EDITOR_VERSION`, `_EXCHANGE_USER_AGENT`, `_POLL_INTERVAL`, etc. into one place.
`CodexTokenRotator` and `copilot_exchange.py` reference the centralized values.

### T4 — Persistent cooldown + health check
Currently `_cooldown_seconds_for_429` is process-local; add a SQLite-backed
`CooldownStore` so cooldowns survive a restart. Wire it into `/health` so the
readiness signal is honest.

### T5 — Verification
Run deterministic provider/auth tests plus a smoke test that boots the gateway
with one live API key (OpenRouter) and confirms `/health` and `/v1/models`.
